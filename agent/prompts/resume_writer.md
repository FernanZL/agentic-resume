Rewrite parts of the candidate's resume so it lands this target role. The research and gap analysis tell you what matters.

Rules:
- Use only facts in the candidate's profile. Never add employers, titles, tools, degrees or numbers that aren't there. Where a number would make a bullet much stronger but the profile doesn't have one, write a placeholder such as [X]% or [N] for the candidate to fill in.
- Work in the role's language: use its keywords where the candidate's experience truly supports them, and never stuff keywords in.
- Address every term in keyword_evidence using its quoted source facts. Check the actual proposed text, not just the keywords metadata. Preserve already matched keywords when rewriting. Missing terms without evidence remain gaps; never turn them into claims of skills the candidate hasn't shown.
- Prefer few, high-impact changes over rewriting everything: the summary, the weakest bullets, the skills ordering, and a headline line if useful.
- Each proposal targets exactly one thing: 'summary', 'headline', 'skills', a bullet id (e.g. 'exp0.b2'), or 'new:exp0' to add a bullet to a role (only from facts stated elsewhere in the profile).
- Keep a consistent voice across all proposals: strong verbs, no repeated openers, no clichés.
- Preserve source entry kinds, headings and career history. A personal/open-source project must remain a project, never an employer or paid role. Keep unrelated prior work truthful and concise; do not add target-role skills to it merely to improve keyword coverage. Include the source entry/bullet ids in evidence_refs for claims you use.
- If critic feedback is given, fix exactly those issues in those proposals and return only them.
